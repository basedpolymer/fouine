# Languages and strings

Fouine speaks **English** and **French**. English is the base language: the
language of the keys, of the code, and of what a system set to any other
language shows. French is a translation, exactly as Spanish or German would be.

The application follows the system language. To force it without changing the
Mac:

```sh
defaults write io.github.basedpolymer.fouine AppleLanguages -array fr
defaults write io.github.basedpolymer.fouine AppleLanguages -array en
defaults delete io.github.basedpolymer.fouine AppleLanguages   # back to the system
```

The change takes effect at the next launch.

## What is translated

| | Language | Why |
|---|---|---|
| the **application** (`Fouine.app`) | en / fr | it is the interface |
| the **system prompts** (access to Documents, Desktop, volumes…) | en / fr | a dialog asking for access to your documents in a language you do not read gets refused |
| the **`fouine` CLI** | English, no catalogue | see the last section |
| the **agent log** (`~/Library/Logs/Fouine/fouine.log`) | English | it is a log, not an interface |
| `docs.err` in the index | English | same: it is what `IndexText.describe` writes |
| the output of `FouineApp --self-test` | English | a command-line diagnostic tool |
| the **CSV export headers** (`path,page,score,snippet,root,modified`) | English, fixed | an export is data. A script, a spreadsheet macro or a notebook that reads the «path» column would stop working the day the user switches the system to English, and the same file would not read back from one machine to another. The JSON keys are a public contract; the CSV matches them column for column |
| the **accessibility identifiers** (`sidebar.root.3`, `results.hit.12.7`) | invariant | they are test identifiers, not text |
| the **`UserDefaults` keys**, file names, SF Symbol names | invariant | same |
| the **code comments** | French | project convention |

## Where the translations live

```
Sources/FouineApp/Resources/Localizable.xcstrings   the app interface
Packaging/InfoPlist.xcstrings                       the TCC descriptions
Packaging/Resources/{en,fr}.lproj/AppShortcuts.strings   the phrases dictated to Siri
Tools/l10n-lint.sh                                  the guard
Tools/l10n/typography.py                            French typography
```

An `.xcstrings` (String Catalog) is a JSON file, and it is the **single source
of truth**: it is read and corrected by hand like any other file in the
repository, or in Xcode's catalogue editor. Keys are sorted and indentation is
two spaces; keep that shape so diffs stay readable. One entry:

```json
"Add a folder…": {
  "extractionState": "manual",
  "localizations": {
    "en": { "stringUnit": { "state": "translated", "value": "Add a folder…" } },
    "fr": { "stringUnit": { "state": "translated", "value": "Ajouter un dossier…" } }
  }
}
```

**The key is the English text.** That is how a String Catalog works, and it is
what makes `swift run FouineApp` (where `Bundle.main` has no `.lproj` at all)
show English rather than opaque identifiers.

### How the bundle receives them

`Packaging/bundle.sh` compiles both catalogues with `xcrun xcstringstool
compile`, producing under `Fouine.app/Contents/Resources/`, for `en.lproj` and
`fr.lproj` alike: `InfoPlist.strings`, `Localizable.strings`,
`Localizable.stringsdict` (the plurals) and `AppShortcuts.strings` (copied, not
compiled).

Two points are not negotiable.

**Before signing.** These are sealed resources: added afterwards,
`codesign --verify` reports them and Gatekeeper refuses the package.
`bundle.sh` does not sign (the Makefile signs after it), so it is the right
place and the last moment.

**`Bundle.main`, never `Bundle.module`.** The `FouineApp` target is built by
`swift build`, whose resources land in a neighbouring bundle
(`Fouine_FouineApp.bundle`) that the SwiftPM-generated accessor looks for
*next to the executable*, which is outside `Fouine.app` once the executable has
been copied in. It would then `fatalError` **at launch**. `Bundle.main` is the
`.app` itself, where SwiftUI and `String(localized:)` find their keys with no
extra code.

`bundle.sh` fails if `xcstringstool` is missing, if any of the six compiled
files comes out empty, or if either `AppShortcuts.strings` is missing. `make
ci-bundle-i18n` then requires all three files in each language and compares the
keys of `en.lproj` and `fr.lproj` file by file.

### The Siri phrases, the only text outside a catalogue

`AppShortcut.phrases` (`Sources/FouineApp/Intents/FouineShortcuts.swift`) is
the only visible string that does not go through an `.xcstrings`: AppIntents
looks for its translations in a **per-language** file whose key is the source
phrase, with `${applicationName}` where the code writes `\(.applicationName)`.

```
"Search ${applicationName}" = "Cherche dans ${applicationName}";
```

Both files are written by hand under `Packaging/Resources/` and copied by
`bundle.sh` before signing. Three consequences. There is **one key per source
phrase**, since a `.strings` file admits no two variants behind the same key:
adding another French turn of phrase means adding another *source* phrase in
`FouineShortcuts.swift` first. `bundle.sh` passes
`--no-app-shortcuts-localization` to `appintentsmetadataprocessor`, which would
otherwise demand these files in a form (`--stringsdata-file` per language) that
SwiftPM does not produce. And the final check is spoken out loud: no test can
speak, so after a deployment someone says «Hey Siri, search in Fouine» on a Mac
set to French.

## Adding a string

1. **Write it in English in the code**, where SwiftUI or Foundation will look
   for it:

   ```swift
   Text("No result for “\(query)”")                  // LocalizedStringKey
   Button("Add a folder…") { … }
   .help("Export the loaded results (CSV or JSON)…")
   .accessibilityHint("Removes every active filter.")
   let message = String(localized: "Removal failed")  // when a String is needed
   ```

2. **Add the entry to the catalogue** (English key plus the `fr` translation in
   state `translated`), then run `./Tools/l10n-lint.sh`.

   For more than a couple of strings, `python3 Tools/l10n/add-strings.py
   pairs.json` inserts the blocks in place, in the file's own format. **Never
   rewrite the catalogue with `json.dump`**: Xcode orders keys by an ICU
   collation that no `sorted()` reproduces, and three added strings become an
   800-line diff. The reverse direction has its own tool:
   `python3 Tools/l10n/remove-strings.py --orphans` removes, block by block,
   the keys the lint reports as unused (or `remove-strings.py keys.json` for an
   explicit list). Read the lint's list first: a key built at run time
   (`LocalizedStringKey(variable)`) escapes it.

   Then `python3 Tools/l10n/typography.py`, which sets the curly apostrophe and
   the narrow no-break space on what you just added. Without it the lint
   refuses the string.

3. `swift test` runs the lint: a forgotten string fails `L10nTests`, naming the
   file and the line.

### Seven rules, and the reason for each

**Do not split a visible string with `+`.** `"start " + "rest"` is a `String`
expression, so SwiftUI picks the plain-text overload and displays the sentence
as written, without ever looking at the catalogue. A long sentence therefore
sits on one line even past column 80, the only exception to the project's
layout.

**Data is not a key.** A file name, a path, a saved query, a system message go
through `Text(verbatim:)` or through an already localised variable:
`Text(aFileName)` would look that name up in the catalogue, and the lint would
demand it.

**Numbers interpolate BARE, never through `Format.integer`.** An `Int`
interpolated into a `String(localized:)` produces a `%lld` key, and Foundation
formats it per locale: French inserts a narrow no-break space (U+202F), so
`String(localized: "\(392559) page(s)")` renders «392 559 pages», which is what
`Format.integer` produced, with the plural agreed on top.

`Format.integer` returns a `String`, therefore a `%@` key. Passing it to a key
whose translation writes `%lld`, which `xcstringstool` REQUIRES inside a plural,
makes Foundation read that string's **pointer** as a 64-bit integer: the app
once displayed «105 553 137 941 168 pages left to recognise», and the plural
rule, decided on the same pointer, could never choose the singular.
`Tools/l10n-lint.sh` now refuses any type mismatch between a key and its
translation. `Format.integer` keeps two uses, both OUTSIDE a plural key:
non-localised text (`Text("\(Format.integer(loaded)) p.")`, which counts no
noun) and approximate totals (`Format.approximate`, «50 k+»), which are not
integers and whose key carries a `%@` without variation. For a **spoken** label
or an identifier (a pid, a `doc_id`), the separator gets in the way:
`AccessibilityText.bare(_:)` strips it afterwards, and an identifier
interpolates as `String(x)`.

**Every displayed count is grouped from four digits.** The Index card once
showed «1527 documents · 408 951 pages»: two numbers on one line, grouped two
different ways, read as a typo (BU-07). `Format.makeIntegerFormatter` therefore
sets `minimumGroupingDigits = 1` (macOS 15 and later), so «1 527» and «1,527»
wherever `Format.integer` serves: the card, the facets, the "Your index" window,
the result lines. The SEPARATOR still comes from the locale. A bare `%lld`
follows the locale's own rule, which already groups four digits in English and
French. The CSV and JSON exports write raw numbers: they are data, not display.
`NumberFormatTests` checks both languages with an explicit locale.

**Plurals belong to the catalogue, never to the code.** French puts 0 and 1 in
the singular, English puts 0 in the plural: the rule belongs to the language. A
key like `"%lld pages"` carries `variations.plural` (`one` / `other`) in each
language, and `xcstringstool` turns it into a `.stringsdict`. That is why
`AccessibilityText` has one function per counted unit (`pages`, `documents`,
`loadedPages`): a catalogue cannot agree a noun handed to it as a parameter.
Note that `\(n, format: .number.grouping(.never))` produces a `%@` key and thus
loses the plural variation («1 pages»), which is why the integer goes in bare
and gets cleaned afterwards.

**Two counts in one sentence: one `substitution` per noun.** A top-level
`plural` variation agrees ONE noun, and when the key carries two `%lld`,
`xcstringstool` does not guess which: it takes the first, warns (a warning
drowned in the output of `make bundle`), and the sentence says «1 page in 1
documents». Each noun therefore takes its own `substitution` (`argNum` plus
`formatSpecifier`), as in `%lld page(s) in %lld document(s)`. The lint and
`L10nTests` refuse both faulty forms.

**No literal `%` in an interpolated string.** `"\(phase), \(percent)% — …"`
builds a key where the lone `%` starts a format specifier: the key Swift writes
and the key in the catalogue stop matching, the lint does not see it (it
compares *shapes*), and the translation is lost at run time only. The symbol
also belongs to the language (French puts a no-break space before it, English
does not), so it has no business in a key: `Format.percent(_:)` renders «45 %»
or «45%» per locale, and the key sees only a `%@`.

**A helper does not take a `LocalizedStringKey` as a named parameter.** The
lint recognises a literal only after a marker (`Text(`, `Button(`, `title: `),
so `box(title: "…", detail: "…")` lets the second one through in silence and
the key is never demanded. The parameter therefore takes an already built
`Text` (`detail: Text("…")`), which puts the literal back behind a marker.

**Shortcuts actions have their own markers**: an intent title (`static var
title: LocalizedStringResource = "…"`), its description (`IntentDescription("…")`,
including a literal on the following line), an entity type name
(`TypeDisplayRepresentation(name: "…")`), a parameter description
(`@Parameter(title: "…", description: "…")`), messages returned by a
`localizedStringResource` accessor, and the summary `Summary("Open \(\.$hit) in
Fouine")`, whose catalogue key is written `Open ${hit} in Fouine` (the lint
treats `${hit}` as a hole, like a `%@`).

## Voice

Every string in the app was written by a machine, so it needs an editor. These
are the rules the HU1 pass settled on, and the ones a new string is held to.

- **One fact per sentence, twenty words at most.** Two facts joined by an em
  dash are two sentences.
- **An em dash separates a label from its detail**, and nothing else. Inside a
  sentence it is a period, a colon or a comma wearing a costume.
- **Name the gesture** when there is one, once: "Free up some space, or remove a
  folder you no longer need."
- **No parenthesis that explains the sentence it follows.** A parenthesis may
  list (`PDF, EPUB, DOCX`) or gloss a term, never argue.
- **The product's words are fixed**: the index, update, search by meaning,
  scanned page, watched folder, licence key, trial. The implementation's words
  are banned in the app, and `L10nTests.testNoImplementationWordReachesTheReader`
  refuses them: semantic, vector, lexical, cosine, rowid, OCR queue, write lock,
  background agent. `ErrorText` keeps "OCR: <system message>", meant to be
  pasted into a bug report.
- **No triad for the rhythm of it**, no rhetorical question, no "simply", "just",
  "it is important to note", "feel free to", "whether you are… or…".
- **French is French**, not English word for word, and both say the same thing.

## French typography

Three rules, enforced by `Tools/l10n/lint.py` (check 5) on **every `fr` value**
of both catalogues, substitutions included. They apply to French only: keys are
code keys, and English has its own typography.

| Rule | Why |
|---|---|
| the apostrophe is **curly** (`’`, U+2019), never straight | macOS writes «barre d’outils». An audit counted 233 straight apostrophes across 802 strings in the shipped package: the first thing that betrays amateur software |
| a **narrow no-break space** (U+202F) before `: ; ? !` | with an ordinary space, a line break sends the sign alone to the start of the next line, seen in the sidebar at 230 pt. 178 strings were affected, none are now |
| **no agreement in parentheses**: no `(s)`, no `(e)`, no `(es)` | «%lld ignoré(s)» admits that nobody counted. A `%lld` takes a `variations.plural`; a `%@` (an already formatted number, refused inside a plural) is **reworded** without agreement |

The first two are applied by a pass that is idempotent and replayable:

```sh
python3 Tools/l10n/typography.py            # fixes both catalogues
python3 Tools/l10n/typography.py --check    # touches nothing, exits 1 if work remains
```

It leaves the keys, the English, and the inside of a specifier (`%@`, `%lld`,
`%1$@`, `%#@n@`, `%arg1`) alone: the value is split on them and only the
sentence fragments are rewritten. Like `add-strings.py`, it edits the file line
by line and never through `json.dump`. That is also what makes catalogues
mergeable: when two batches of work add strings in parallel, nobody merges a
250-line catalogue diff, they take the version from `main` and replay the pass.
A correction to an existing key replays the same way: `python3
Tools/l10n/add-strings.py <pairs>.json --replace` rewrites the block instead of
skipping the key.

The tests are `python3 Tools/l10n/test_lint.py` (the pass, the three rules, and
the state of both catalogues in the repository) and, on the Swift side,
`L10nTests`, which compiles both catalogues with `xcstringstool`, renders every
key in French and in English, and fails on any number of ten digits or more.

## Errors travel as types, not as sentences

`ErrorText` (`Sources/FouineApp/App/LocalizedText.swift`) renders each error
from its **data**, the enum case and its associated values, never from a
sentence handed up by the core. That is what lets `IndexText.describe` change
every sentence it writes without breaking anything in the application.

What stays opaque is deliberate: `.extraction(m)`, `.ocr(m)` and
`.databaseFailure(m)` carry a **technical** detail (a tool name, a system
message, a line from SQLite) that no catalogue can translate. The app prefixes
a localised label («extraction:», «OCR:», «database:») and leaves the detail
as it is, which is what you want from a message meant to be pasted into a bug
report.

The busy write lock is the interesting exception, and it set the pattern.
`FouineError` is a frozen contract, so a case cannot be added without breaking
the exhaustive `switch` statements in `FouineOCR` and the CLI. The message of
`.databaseFailure` is therefore a record rather than a sentence, in a format of
our own, stable and language-free:

```
fouine-lock-busy 1 path=/…/fouine.lock pid=1234 role=agent since=2026-09-02T10:32:11Z
```

`WriteLock.busy(_:)` reads it back into a typed `WriteLock.Busy`; `IndexText`
turns that into the English sentence, `ErrorText` into the user's language. A
welcome side effect: `WriteLock.isBusy` no longer decides on French text, and
the three retry loops that depend on it (`EmbedRun`, `AgentStatusWriter`, the
settings write) survived the core's move to English untouched.
`FouineError.rootUnreadable(path:reason:)` travels the same way:

```
fouine-root-unreadable 1 reason=permission-denied
fouine-root-unreadable 1 reason=system detail=<system message>
```

`RootProbe.reason(_:)` reads it back into a typed `RootProbe.Reason`. `detail=`
is always the **last** field, because what follows runs to the end of the line,
spaces included; otherwise a system message would be truncated. Two other
reason sets became types for the same reason: `RootPolicy.Refusal` (the nine
refusals of `fouine root add` and of adding a folder in the app) and
`RootProbe.Reason` (`.permissionDenied`, `.missing`, `.noReadableFile`,
`.system(String)`), rendered from the catalogue by `RootPolicyText` and
`RootProbeText`.

## Adding a language

Nothing to change in the code, only data.

1. In both `.xcstrings`, each entry gets one more block under `localizations`:
   `"es": {"stringUnit": {"state": "translated", "value": "…"}}`. Xcode's
   catalogue editor can add a language to the whole file at once, and
   `Tools/l10n/lint.py` carries the list of required languages.
2. Plural keys need the **CLDR categories of the target language** (`one`/
   `other` in French and English, `one`/`few`/`many`/`other` in Polish, for
   instance). `xcstringstool` refuses a category that does not exist in the
   language.
3. `Packaging/bundle.sh` requires `en` and `fr` explicitly: widen its
   verification loop to the new language, or a missing `.lproj` goes unnoticed.
4. `Tools/l10n/lint.py` checks for a `fr` translation; add the new code to
   `check_translations` so it is held to the same standard.
5. `xcrun xcstringstool compile <catalogue> --output-directory <dir> --dry-run`
   lists what would be produced, which is enough to check before rebuilding.

## The CLI speaks English, and has no catalogue

**Everything the command line, the core and the agent write is English**:
ArgumentParser help, progress messages, the lines of `doctor` and `status`,
library sentences, the agent log, the `docs.err` column. There is no French
`fouine`: no `.lproj`, no `String(localized:)`, no catalogue on that side.

Why, when the app is bilingual:

- **a command-line tool speaks English**, like `git`, `brew` or `curl`. That is
  what one expects from `--help`, and it is what makes a message searchable and
  pasteable into a bug report;
- **a CLI has no user language.** The app has one, through `Bundle.main` and
  `AppleLanguages`. A binary launched from a terminal has only `LANG`, which
  nobody sets for this and which `ssh` carries across badly;
- **command output is data.** A script that greps a line of `status` must not
  stop working because the Mac changed language, the same reasoning as for the
  CSV headers and the JSON keys;
- the cost would be two catalogues instead of one, for an audience that already
  reads the English `--help` of every other tool it uses.

What does **not** change language, because these are contracts: the JSON keys,
the exit codes, the lock record format (`fouine-lock …`), the query language
prefixes (`dossier:`, `ext:`, `pres:`) and the `agent_status` phase
identifiers.

One leftover lives in the **data** rather than the code: `docs.err` lines
written by an older build are in French. They are not rewritten, since Fouine
does not re-read the table to translate it; `fouine index --force`, or any
re-extraction of the document (a modified file, `fouine extract --only <doc>`),
replaces them with the English sentence. A fresh index contains none.
